### 🏗️ Блок 2: Архитектурная оптимизация (вечер)

#### 🧹 Очистка кода
- 🗑️ **Удалён `PlayerDatabase.gd`** — дублирующий мёртвый код, который нигде не использовался
- 🧽 **`CardDatabase.gd`** — убран неиспользуемый кэш имён (`players_by_name_lower`, `_add_to_name_cache`, `get_player_id_by_name_lower`)

#### 💾 Оптимизация сохранений
- 🔄 **`SaveManager.gd`** — добавлены атомарные методы:
  - `save_lineup_and_subs(lineup, subs)` — одна запись на диск вместо двух
  - `save_formation(formation)` — консистентное сохранение схемы
- 🔄 **`ClubManager.gd`** — все методы (`set_player_in_lineup`, `move_to_substitutes`, `move_to_lineup` и др.) теперь используют атомарные сохранения

#### 📂 Вынос данных из кода
- 🆕 **`res://data/formations.json`** — 17 тактических схем вынесены из хардкода
- 🆕 **`FormationManager.gd`** (Autoload) — централизованная загрузка схем
- 🔄 **`SquadScreen.gd`** — убрано ~100 строк захардкоженных схем
- 🔄 **`FormationSelectScreen.gd`** — теперь динамически показывает 4 случайные схемы из общего пула

#### 🚀 Object Pooling для карточек
- 🆕 **`CardUIPool.gd`** (Autoload `CardPool`) — пул объектов для `CardUI`:
  - Предзагрузка 30 карточек при старте
  - Методы `acquire_card()` / `release_card()` / `release_all_cards()`
  - Лимит 100 активных карточек
- 🔄 **`CardUI.gd`** — добавлен метод `reset()` для сброса состояния при возврате в пул
- 🔄 **`SquadScreen.gd`** — `_refresh_substitutes()` и `_open_player_selector()` теперь используют `CardPool`

#### 🛡️ Строгая типизация
- Исправлены все предупреждения `Variant inference` через явное указание типов:
  - `var raw_slots: Array = formations.get(...)`
  - `var card_node: CardUI = CardPool.acquire_card()`
  - `var slots: Array = formations_data[key]`
- Разрешён конфликт имён `CardUIPool` ↔ `CardPool` (autoload переименован)
